Audit of `b45201f` (origin/main, last commit 2026-09-26), run 2026-10-14.
Thirteen parallel read-only auditors each covered one slice: every crate,
the Java mod, tooling/CI, docs, cross-cutting security, and the loader contract
plus git state. The coordinating session ran the full build, tests, gates and
live render check on the owner's machine and independently re-checked every
finding marked ✔ against the code, git, or the local 26.2 decompile.

Read with `docs/REVIEW-2026-09.md`: this audit re-grades that review's claims
(§7) and adds what it missed.

## 4. Medium-severity findings

**Launcher / auth**
- `auth/service.rs:203-211`: the Minecraft token is refreshed only when *empty*. `expires_in` is parsed and dropped (`chain.rs:59,192`). A launcher open more than about 24 h passes an expired token. ✔
- `main.rs:741-758`: a signed-in account with no live token yet (refresh in flight or failed) silently launches **offline** as `<instance name>`, with no warning.
- `events.rs:1535-1544,1626`: social `/api/links/by-uuid` probes and 15 s `server-status` polls run for every MS-signed-in account, not only linked ones. This contradicts CLAUDE.md ("once the user links an account").
- `chain.rs:311`: a refresh response without a `refresh_token` stores `""`, so the account is signed out on the next start. A late `Success` for account A can override a switch to B (`service.rs:108-120`).
- `finish_launch` → `pick_jre` cold-scans (`java -version`, `where java`) on the UI thread after a JRE install.

**In-game HUD (`ewo-jni` / Java)**
- `EwoFrameHook.java:20-57`: no try/catch around `nativeRender`/`EwoModules.tick`. Any `UnsatisfiedLinkError` (stale DLL; there is no ABI version handshake) or NPE crashes Minecraft's render loop.
- `mixin/MinecraftShutdownMixin.java:29`: `@Inject(method="destroy", require=0)`. 26.2's `Minecraft` has `close()` and `stop()` and **no `destroy()`** (decompile lines 1109/1565). The primary exit-watchdog arm is a silent no-op on 26.2, which weakens the 2026-07 zombie-JVM fix. ✔
- `EwoModules.java:125,146`: `Class.forName("dev.lewlone.ewohud.assist.EwoAssist")` puts the assist class name in the **legit** jar's constant pool, the fingerprint the post-ban refactor meant to remove. `build.ps1` has no post-build assertion. ✔
- `lib.rs:576-610` `Hud::create`: GL init runs with no context-restore guard (the crash class the guard exists for). Closing the overlay mid-drag strands drag state, which later saves a widget snapped to the edge.
- Cross-language pin is weak: `schema_version_matches_the_java_mirror` asserts a Rust literal and never reads the Java file; HUD schema 10 has no pin at all. (The values do match today.)

**Rewo protocol**
- `rewo-proto/src/nbt.rs:140-146`: NBT strings use `from_utf8_lossy`, not Java modified UTF-8. Every emoji in chat, sign, item or scoreboard NBT renders as U+FFFD garbage.
- `play/outgoing.rs:240`: `send_command` parses with `blocks: None, items: None`, so `/execute if block …` and item-predicate commands go out unsigned and a secure-profile server rejects them.
- `lib.rs:405-408`: a negative login compression threshold is kept (vanilla disables compression). Login `custom_query`/`cookie_request` are ignored, so the login stalls 30 s.
- `chat_log: Vec<String>` is never drained in `live`, so it grows all session. The packet queue is bounded by frame count, not bytes.
- Several malformed packets are dropped or partially applied **without** `decode_failures` (mob effects, `light_update`, biomes, `player_info_update`, `set_health`, `registry_data`, `section_blocks_update`), contrary to REVIEW-09's "counted" row.

**Rewo simulation / render**
- `rewo-world/src/chunk.rs:556-557`: `light_update` ignores the **empty-section masks** (`_empty_block` discarded). Vanilla `readSectionList` queues a zeroed `DataLayer` for them, so a removed torch's glow can stay. ✔ (against the decompile)
- `chunk.rs:190-215`: `Column::set_light` compares against the raw section value (0) instead of the implicit-15 sky above `sky_full_above`, so in omitted sections darkening writes are no-ops. The incremental==full property test covers one column only, never cross-column or sparse sky.
- `rewo-mesh/src/pool.rs`: no rayon `panic_handler`. Any future mesher panic aborts the process. (No current trigger found.)
- `rewo-gpu`: `renderer.rs:314` stores depth `DONT_CARE`, but `in_gamma_space` ends rendering and reopens with `LOAD` (`world.rs:2233-2279`). Depth is spec-undefined for glint/crumbling/velvet text. Fine on desktop NV/AMD/Intel, invisible to sync validation. ✔
- `rewo-gpu/src/velvet_text.rs:171-206`: every new glyph rebuilds the atlas with a blocking queue-draining fence on the gameplay path. The comment claims "no idle".
- `live_cmd/input.rs:560,577`: **chat cursor grab inverted.** Opening chat confines and hides the cursor; closing it frees the cursor in play. ✔

**Rewo app / gates boundary**
- CI builds, tests and lints only with `--features rewo-app/gates`. The **shipped configuration** (`package.ps1`, default features) is never compiled in CI.
- `main.rs:481`: `tracy_client::Client::start()` runs in the shipped `rewo` (default tracy features include LAN broadcast), at odds with "nothing phones home".
- `render_check.rs` (2.9k lines) and ~29 witness blocks are compiled into production. `rewo-gpu` reads `REWO_MOB_DEBUG_TEX`, `REWO_FOG` and `REWO_NO_SYNC_VALIDATION` directly, bypassing `knobs`. `rewo-mesh/oracle` is enabled unconditionally.
- `options.txt` is a relative path (`sky.rs:177`). The launcher sets no `current_dir`, so it lands in the launcher's CWD, not the game dir as documented.

**Gates / tests**
- 6 GPU gates (mobshot, mobtexshot, itemshot, healthbarshot, hurtshot, labelshot) don't fail when validation is inactive. Under `--release` they pass unvalidated.
- `gates.py`: no pinned gate set (a gate dropping out of `--help` silently shrinks the sweep). `demo` output is not scanned for VUIDs. `--release --audio` builds the bogus feature `--release,audio`. Audio witnesses and the mobshot `--emissive/--etf/--tint/--variant-check` sub-gates are never automated.
- `mobshot` can print "OK — 0 mob-views" (no floor). `containershot` only requires `> 0`.
- 10 tests still `return` silently without `skip_test!` (`rewo-data` `mob_effects.rs` ×4, `recipe_display.rs` ×4, `decode.rs` ×2), so REVIEW-09's "Fixed" row is partly false. ✔
- `fuel_table.rs` (generated, "Do not edit") carries 4 hand-added tests its generator would delete.
- Coverage holes: `ewo-render` 0 tests; `ewo-jni` 3; launcher `main.rs`/`events.rs`/`auth/chain.rs`/`social`/`runtime` extractors 0; `rewo-net` login/config/signing nearly untested (`signed_layout_prefix_is_stable` is vacuous); no Java build or mixin-target check in CI.

**Audio**
- `mixer.rs:227-240,403`: the cpal callback allocates and frees (`Arc::new(Pcm)`, `Vec` growth, dropping `Arc<Pcm>`), more than its header admits.
- Decode workers have no `catch_unwind`. A panicked worker leaves parked channels un-reclaimable (pool slot leak). Device loss is only counted; audio stays dead until restart.

**Repo / tooling / loader**
- `LICENSE` is MIT; every crate says `license = "Proprietary"`. Decide. ~20k lines of Mojang-derived tables and ~255 decompile excerpts in doc comments sit in a public repo: worth a deliberate call.
- CI clippy has no `-D warnings`, no `cargo fmt --check`, no MSRV job (1.89 claimed, floating stable), no `cargo audit`/Dependabot, no `permissions:` block; `gates.yml` keeps the checkout token on a persistent self-hosted workspace.
- Loader manifests' `ewo-hud` URL is `file:///…/EwoClientV3/ingame-mod/build/ewo-hud-0.1.0.jar` (the **stale main checkout**, jar dated Aug 23). `file://` sources are always re-copied at launch, so it overwrites a newer deployed HUD jar.
- EwoLoaderV1: `forcecrawl` exists only as **uncommitted** edits (+ a gitignored jar). The `ewo-loader` manifest sha1/size don't match the current fat jar (invisible because `file://` isn't hashed).
- `ewo-core/src/pvp.rs`: non-atomic `pvp.toml` write the Java side polls; `%APPDATA%`-only (no XDG); unvalidated profile names joined into paths.
