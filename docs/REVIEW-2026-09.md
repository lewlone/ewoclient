# Independent review — September 2026

A critical review of the whole workspace at `0fd9ced` (post-M180), followed by
a fix pass. Each finding below was confirmed by reading the code; the most
severe ones were re-checked by the reviewer before fixing. "Open" means open.

The review's main conclusion: the code's low-level decoding and the per-feature
vanilla transcriptions are generally careful, but the docs reported
measurements on narrow paths as general correctness ("0 VUIDs" without
synchronization validation, "CORRECTIONS 0" on flat-ground walking only,
"0 light mismatches" on the full-recompute path rather than the incremental
one play uses). Around the careful cores, lifecycle, error handling and
destructive operations had real bugs.

## Launcher (`ewo-launcher`, `ewo-render`)

| Finding | Status |
|---|---|
| Any native-extraction failure killed **every windowless `java.exe` on the machine** (test servers, Gradle). | Fixed: only launcher-recorded PIDs, verified by creation time, only on file-in-use errors. |
| `last-launch.pid` could kill an unrelated process after PID reuse. | Fixed: PID + creation time. |
| `--accessToken` logged at info on every launch; social token printed via `Debug`. | Fixed: redaction + hand-written `Debug`. |
| Child JVM / rewo inherited the launcher env incl. `EWO_LOADER_TOKEN` (readable by all bundled mods). | Fixed: `*TOKEN*`/`*SECRET*` vars removed. |
| Instance folders keyed by display name: rename orphaned worlds; names allowed `..` and path separators. | Fixed: stable `id` folders, migration keeps existing folders, name validation. |
| Config parse failure silently replaced instances/accounts with defaults, then saved over the file; no atomic writes. | Fixed: `.bak-<ts>` on parse failure, one atomic write helper, 0600 `auth.toml` on Unix. |
| Zip-slip via absolute paths; tar `unpack` instead of `unpack_in`; unfiltered manifest paths; panic on short asset hash. | Fixed. |
| Existing same-size files trusted without hash; JRE sha256 skipped on size match; no `.part` download. | Fixed (hash results cached per session by path/size/mtime). |
| Loader manifests accepted over plain `http://`; an https manifest could list `file://` libraries. | Fixed. |
| Failed downloads could not be retried without a restart. | Fixed. |
| Launch did blocking network + `sleep` on the UI thread. | Fixed: `launch/prepare.rs` worker. |
| OAuth loopback honoured `?error=` before checking `state`. | Fixed. |
| `file_url_to_path` mangled non-ASCII paths. | Fixed. |
| Main menu polled the social API for signed-out users; Telemetry toggle does nothing. | Fixed (sign-in gated); the toggle is documented as having no backend. |
| Case-insensitive filesystem vs case-sensitive profile names. | Fixed. |
| `LEAK_HUNT_INSTRUMENT` counting allocator shipped in release. | Removed (the foreground-skip fix and deferred cleanup stay). |
| D3D `ResizeBuffers` panicked on device loss; `Present` result ignored. | Fixed: the device stack is rebuilt with backoff and cached GPU images invalidated; verified with a real `RemoveDevice` (`examples/device_loss.rs`). |
| `ewo-ui` was an empty crate the launcher depended on. | Deleted. |
| `auth.toml` stores refresh tokens in plaintext. | Fixed on Windows: DPAPI-sealed (`auth/secret.rs`); legacy plaintext migrates on load; an unopenable token signs out only that account. Linux keeps a 0600 plaintext file (keyring integration open). |
| Deleting an instance leaves its folder on disk. | Open (by design for now; a new instance never reuses it). |
| `main.rs` `window_event` is ~2,400 lines with no tests. | Partly: window hit-testing, instance operations and the Launch-click decision (`launch_slot.rs`) moved out and unit-tested. **Open:** `window_event` itself is still ~2,400 lines. |

## Rewo simulation (`rewo-world`, `rewo-mesh`, `rewo-data`)

| Finding | Status |
|---|---|
| The mesher treated anything that renders as a cube as opaque, so faces behind glass, leaves and ice were culled (visible holes). | Fixed: per-state face occlusion + vanilla `skipRendering`; translucent blocks go to the blended pass (stained glass was invisible). Demo PNG changed intentionally — see `git log tools/demo_hash.txt`. |
| Collision shapes derived from render models via an allow-list; glass panes, bars, chains, lanterns, bells, rods, ... had no collision. | Fixed: `tools/gen_collision_shapes.py` extracts shapes from the decompiled block classes (model fallback for the rest). Scaffolding, powder-snow landing box, dripleaf tilt and random offsets are not modelled. |
| Collision scan skipped the one-block shell for tall shapes (fences/walls jumpable, fall through fence tops). | Fixed. |
| Physics was the flat-ground walk loop: no fluids, climbing, block friction/speed factors, stuck-in blocks, sneak edge guard, attributes, axis order. | Fixed (ported from the decompile) and wired into the live session with attributes and movement effects (jump boost, slow falling, levitation, dolphin's grace) from the server; bubble columns, honey sliding and water/lava currents (`FlowingFluid.getFlow`) followed. Currents approximate `blocksMotion` as "has collision boxes" and skip the ice exemption. Poses followed (crouch 1.5 / swim-crawl 0.6 boxes and eye heights, `updateSwimming`, `updatePlayerPose`, `moveTowardsClosestSpace`, swim steering), and the Nether's fast lava. `play` shows 0 corrections on plain, soul sand, packed ice and water. Elytra glide (`updateFallFlyingMovement`) and the START_FALL_FLYING take-off followed; the glide state is the server's shared flag, set optimistically on take-off as vanilla does. Entity colliders followed (`canBeCollidedWith`: boats/rafts, live shulkers, adult happy ghasts one stands on; the ridden vehicle excluded). **Open (minor):** the pose-fit test ignores entities; a hovering happy ghast is not a collider (its still-timeout never reaches a client). |
| Incremental light (the path play uses) was never compared to the server; slabs/stairs under open sky kept sky 15 below. | Fixed plus two further bugs it exposed; a random-edit property test checks incremental == full recompute. |
| `section_blocks_update` relit per block. | Fixed: one batched pass per packet. |
| Block edits accumulated in an override hash map never folded into the chunk storage. | Fixed: written through; chunk cache format bumped to 2. |
| Column map used SipHash on the hot path. | Fixed: Fx hash. |
| Unpacked `u32` section storage (~16 KB per section). | Fixed: `u16` cells (8 KB); oversized ids are rejected, never truncated; cache format unchanged. |
| Smooth lighting / continuous AO. | Fixed: `BlockModelLighter` ported (`smooth_light.rs`) and used for every quad of an AO model, flat lighting otherwise, as `tesselateBlock` chooses. The vertex now carries vanilla's 8-bit color (`gray`, cardinal scale, tint multiply) and smooth light coordinates; the lightmap is sampled per vertex from RGBA8 texels with bilinear filtering, as vanilla's `sample_lightmap` does. The per-state facts it reads beyond the collision table (view blocking, 0.2 shade, emissive rendering, model AO) are extracted from the decompile (`tools/gen_ao_facts.py`); shulker boxes are baked as closed. This also fixed unshaded quads and fluid sides in the Nether (`up()` = 0.9, `up() * north()`) and fluid light (`max(pos, above)`). The Smooth Lighting option (`ao`) is on a Video Settings page and remeshes every loaded column when changed. |
| UI screen models live in `rewo-world`. | **Open** (structural). |

Live check after wiring (fresh vanilla server via `rewo play`): 0 corrections on
grass, soul sand, packed ice and in water; build actions accepted; light check
exact. The server's movement check is lenient, so this shows the new physics is
not wrong in ways the server rejects; bit-exactness rests on the unit tests,
which assert vanilla's formulas.
